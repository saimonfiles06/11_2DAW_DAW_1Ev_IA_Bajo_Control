# Respuesta prompt débil

¡Claro! Te ayudo a preparar la documentación completa de tu proyecto, bien estructurada y lista para entregar o publicar.

**Pásame el proyecto** (puedes adjuntar los archivos, el código fuente, un ZIP o el documento que tengas) y prepararé la documentación basándome en su contenido real.

La documentación puede incluir:

- **Introducción y objetivos:** qué es el proyecto, qué problema resuelve y para qué sirve.
- **Requisitos:** tecnologías, dependencias y requisitos del sistema.
- **Arquitectura:** estructura, componentes, módulos y cómo se relacionan.
- **Instalación y configuración:** pasos para ejecutar el proyecto.
- **Funcionamiento:** explicación de las funcionalidades principales.
- **Uso de la aplicación:** instrucciones y ejemplos.
- **API y base de datos:** endpoints, modelos y relaciones, si existen.
- **Pruebas y posibles mejoras:** validaciones, limitaciones y futuras ampliaciones.

También puedo organizarla en un `README.md`, un documento técnico formal o una memoria de proyecto lista para entregar.

Para adaptarla a lo que necesitas, dime un poco más:

**Siguiente paso:** adjunta los archivos del proyecto aquí. Revisaré su estructura y generaré la documentación con información específica de tu código, sin inventar funcionalidades ni detalles técnicos.

# Respuesta prompt fuerte

Perfecto. Asumiré el papel de **desarrollador sénior y responsable de documentación técnica**. El objetivo será generar un `README.md` fiel al estado real del proyecto, revisar su coherencia con los archivos y el código, y documentar de forma trazable el banco de prompts y su evolución en Git.

Para hacerlo correctamente, necesito revisar el proyecto antes de redactar la versión definitiva.

## **Qué voy a revisar y entregar**

**1. README.md completo**

Descripción, objetivos, requisitos, instalación, ejecución, estructura, funcionalidades, pruebas, limitaciones, referencias y banco de prompts.

**2. Auditoría técnica**

Contrastaré los comandos con los archivos de configuración, verificaré las rutas y dependencias documentadas e identificaré contradicciones y datos pendientes de confirmar.

**3. Documentación del banco de prompts**

Inventario de prompts y ejemplos existentes, finalidad, entradas, salidas esperadas y criterios de evaluación, siempre que los archivos permitan confirmarlos.

**4. Historial Git propuesto**

Secuencia coherente de commits descriptivos, con alcance definido y orden lógico. Diferenciaré los commits propuestos de los que realmente se hayan ejecutado.

## **Estructura prevista del README**

1. Nombre y descripción del proyecto.
2. Objetivos y alcance.
3. Tecnologías y requisitos previos.
4. Instalación, configuración y ejecución.
5. Estructura del repositorio.
6. Funcionalidades principales.
7. Banco de prompts y ejemplos de uso.
8. Pruebas y resultados verificados.
9. Limitaciones conocidas y trabajo pendiente.
10. Fuentes, referencias y licencias pertinentes.
11. Historial de cambios de la documentación, si procede.

La estructura definitiva se adaptará al proyecto: no incluiré secciones vacías ni presentaré como realizadas pruebas que no se hayan ejecutado o cuyos resultados no estén disponibles.

## **Qué necesito ahora**

**Adjunta el proyecto**, preferiblemente como archivo ZIP con el código, los archivos de configuración, las pruebas y el banco de prompts. Si está en un repositorio Git, incluye también el historial o un archivo de registro de commits si quieres que lo revise.

Si solo tienes algunos archivos, envíalos igualmente y trabajaré con la información disponible.

Cuando los reciba, seguiré este proceso:

- Inspeccionar los archivos y determinar el estado real del proyecto.
- Contrastar cada sección del README con las evidencias disponibles.
- Corregir errores, omisiones y contradicciones.
- Preparar el `README.md` final y una propuesta de commits ordenados.
- Señalar explícitamente cualquier aspecto que no haya podido verificar.

**Importante:** no afirmaré que he modificado el repositorio ni ejecutado comandos Git si no he tenido acceso para hacerlo. Si únicamente puedo trabajar con los archivos adjuntos, te entregaré el README revisado y los comandos necesarios para incorporarlo.
